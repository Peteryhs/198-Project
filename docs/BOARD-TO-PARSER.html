What the firmware sends

The UNO R4 Minima sketch writes text to Serial1 at the specified 115200 baud. The stdlib Python parser runs on the AR9331 shield and returns R lines followed by one final V. The intended Linux port is /dev/ttyATH0; that mapping has not been confirmed on hardware.

Sensor 1 is on A0–A2 (upper arm); sensor 2 is on A3–A5 (forearm), both on one limb. The sketch configures 10-bit ADC results with analogReadResolution(10); the UNO R4 Minima operates at nominal 5 V. USB supplies roughly 4.7 V to the MCU through a Schottky diode, but that is not a measurement of the ADC reference on this assembled stack. Sources: hardware source audit, U/C evidence and the committed sketch. The inherited conversion (ADC - 338) * 0.0148 is uncalibrated. unit=g and range=3 are protocol metadata, not measured proof of accurate g or clipping limits. Reported g is nominal and unverified; pass through sensor values without clamping at ±3 g. Nothing here has run on the physical board. See the hardening and operations handover before deployment.

3Once, when the set ends

E donethe set is complete E abortedcancelled, non-finite reading, or sampling deadline missed; discard the set E overflowspecified sample cap reached; discard the set

Send one of these, once, at the end of every set.

4The four things that break it

  • Decimals. The committed sender prints a sign and eight decimals, like +0.05123456. Gravity remains in the nominal, uncalibrated g values; the printed precision does not establish physical accuracy.
  • Sample number. Starts at 0 for each set and adds 1 every line. A skip or a repeat makes the whole set invalid.
  • Time. Whole milliseconds since the set started, and it must increase every line. Take the value from one clock, either millis() or micros() / 1000, and use the same clock for both sensors.
  • One sensor only. If a reading fails, send E aborted and stop the set. Never substitute zeros for missing readings or send half a paired sample. A real zero-valued axis is valid.

6What comes back

Use the shield entry point after verifying the UART mapping and stopping competing readers: python3 -B -u scripts/tally_stdlib.py --port /dev/ttyATH0 --quiet --reply port. Install both side models for this command; a single-side installation needs --side L or --side R. The side comes from each header. The JSON fields below are diagnostics, not serial reply tokens.

fieldmeaning
verdictcorrect or wrong for the whole set, or null when the set could not be scored.
mean_p_wrongMean probability of wrong form. The verdict is wrong at 0.5 or above.
exerciseEAH, EFE or SQZ.
statusscored. Anything else carries diagnostics and no verdict.

Illustrative reply values only. For a scored set, the parser sends R <index> <verdict> <p_wrong> <exercise> <duration_s> for each detected repetition, then one V. An unscorable set sends only V unknown nan -. Rep labels are pseudo-label estimates inherited from whole sets; they do not establish which repetition was bad. The committed sketch handles V only and logs R as invalid; test reply bursts with USB attached and absent before release. The receiver merge snippets are in the firmware handoff.

The procd service writes bounded, volatile diagnostics under RAM-backed /tmp: each log has a 128 KiB current file and one 128 KiB backup, for at most 512 KiB across both paths. The command above writes no reply log. Only V completes the firmware wait. Its specified timeout is 30 seconds; after timeout, prevent Start and restart Python and reset the Arduino together. A missing end marker, lost reply, or brownout may require that same recovery. No transaction IDs exist.

Reported measured series-level quality accuracy is 91.03 % left and 88.89 % right, evaluated LOSO by subject over 30 subjects (301 left and 306 right sets); estimated majority floor: about 50 %. Source: AGENTS.md. These are offline results, not board measurements or independently validated repetition accuracy. No physical board has executed this parser.
