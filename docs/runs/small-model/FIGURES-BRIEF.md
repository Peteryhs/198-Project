# Figures brief — 198 form model progress, on the repo brand kit

The data is in `docs/runs/small-model/figures/`, generated by
`scripts/export_progress_tables.py` from committed run outputs. The look comes from
`docs/brand/BRAND.md` and the SVGs beside it. Read both before writing any plotting code.

## The one-sentence story

A model that could not run on the board (2.5 MB, 107,528 nodes, 20× the flash budget) became
one that does (13 KB of arrays, 1,450 nodes) without losing accuracy — the linked sketch is
96,164 B of a 262,144 B budget.

## Brand rules that bind these figures

Authority is `docs/brand/BRAND.md`. Do not invent colours.

| Role | Hex | Use in a figure |
| --- | --- | --- |
| Ink | `#1C1917` | all type, axes, hairlines, the existing model |
| Paper | `#F5F0E6` | figure ground, every plot area |
| Clay | `#9A3B12` | the ONE accent: the selected model, the budget line, the key number |
| Sage | `#3F5A46` | state only — correctness, "fits" — never a second series colour |
| Ash | `#6B6157` | secondary labels, reference/old model, annotations |

- **Clay is the only accent.** A figure uses Ink plus one accent, and Clay wins every time.
  A second series is Ash, not a new hue. If a chart seems to need three colours, split it.
- **Sage only for state**, e.g. the "fits under budget" band. Never style a series with it.
- **Type:** Fraunces semibold for a headline inside the figure; Inter for every number, tick
  and label. Both must be resolved by name, not by a font-file guess.
  This box currently has neither installed (`fc-match Fraunces` → Noto Sans), and
  matplotlib is not in `.venv`. Install both, then confirm with `fc-match` and say in the
  report which face actually rendered. If you fall back, name the fallback in the caption.
- **No chartjunk:** no gridlines except faint horizontal hairlines in Ink at 8% alpha, no
  frames, no shadows, no gradients, no 3-D, no pie charts, no legend box — label series
  directly at their end point.
- **Numbers:** one decimal, no trailing zeros beyond it, thousands separated, and units in
  the axis label (`LOSO accuracy, %`, `Flash used, kB`).
- **The mark** (`docs/brand/form-mark-ink.svg`) belongs on the cover figure only, bottom
  left, at about 48 px. Not on every chart.
- Output 1600×900 at 2× (PNG), paper ground, saved next to the data.

## Chart 1 — accuracy vs model size (the main chart)

Data: `candidates-size-vs-accuracy.csv` (38 rows).

- x `nodes` on a log scale (125 → 114,860), y `loso_accuracy_pct`.
- Ink for the reference forest points, Clay for the two `selected` points, Ash small dots for
  everything rejected. Annotate directly: "rep 1,450 nodes, 89.3%", "window 2,900, 81.1%",
  "shipped RF, 107,528 nodes, 88.3% (does not fit)".
- Vertical Clay dashed line at 10,000 nodes, labelled "budget ceiling (120 kB)".
- Title inside the figure: **Same accuracy, 1/70th the model.**

## Chart 2 — progress ladder, overall

Data: `per-exercise.csv` (rows where `exercise = ALL`) plus chance from `headline.csv`.

- Two panels, rep and window. Bars: chance (Ash, hatched), logistic regression (Ash),
  reference RF (Ink), new small model (Clay).
- Chance is 50.0% for series and **49.85% for window rows** — label it "chance 49.9%".
- Value labels on top of each bar, one decimal.

## Chart 3 — where the change lands, per exercise

Data: `per-exercise.csv` (rows where `exercise != ALL`).

- Grouped bars per exercise: reference RF in Ink, small model in Clay, `delta_vs_reference_pp`
  printed on the Clay bar.
- Caption must carry the trade: window model loses 1.28 points on SQZ to gain 1.26 on EFE;
  the rep EAH loss is 10 series out of 464.

## Chart 4 — what fits in 262 kB

Data: `footprint.csv`.

- Horizontal stacked bar of the 262,144 B limit: empty sketch 38,984, both model objects
  39,890, remaining free 183,270. Ink for the sketch, Clay for the models, Paper with a
  hairline for free space; label "96,164 B linked" at the end of the used segment.
- Second, shorter bar for RAM: 22,824 used of 32,768.
- Caption: only 96,164 B is a linked measurement; model-object bytes are object sizes, not
  linked flash.

## Chart 5 — why 3 s windows

Data: `window-length-sweep.csv` (rerun baselines in `docs/RESULTS.md`).

- Lines over window seconds 1/2/3: logreg Ash, rf Ink, hgb Clay. End-point labels, no legend.
- Purpose: shows the window length was settled, not still being tuned.

## Caption rules

- Every figure: "LOSO over 30 volunteers, 1,368 series / 29,871 windows, chance 49.9–50.0%".
- Hyperparameters were chosen on the same LOSO folds they are scored on, so the new numbers
  carry roughly a point of selection optimism. Print that on chart 1 and chart 2.
- Rep numbers are series-level (1,368); window numbers are window-level (29,871 rows,
  correlated within a volunteer). Never share an axis without saying so.
