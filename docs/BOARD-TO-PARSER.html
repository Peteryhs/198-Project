What the firmware sends

The sketch writes text to Serial1 at 115200 baud. Three kinds of line go out. Python on the Linux side reads them and sends back one verdict for the set.

1Once, when the sketch starts

#TALLY2 fs=100 unit=g range=3 side=L
#TALLY2the record name fs=100fixed unit=gfixed range=3the sensor range you use side=Lthe arm you mounted: L or R

One line, sent once after reset.

2Every 10 milliseconds

S 12 340 +0.05123456 -0.01834567 +0.99321234 +0.10769876 -0.02915432 +0.97180000
S 12 340sample number, then milliseconds since the set started +0.05123456 -0.01834567 +0.99321234upper arm, in g: x, y, z +0.10769876 -0.02915432 +0.97180000forearm, in g: x, y, z

That is one line, split below so you can see which number is which. Six numbers for two sensors, both read in the same tick.

3Once, when the set ends

E donethe set is complete E aborteda sensor failed; the set is thrown away

Send one of these, once, at the end of every set.

4The four things that break it

  • Decimals. Each of the six numbers needs eight decimals and a printed sign, like +0.05123456. Send in g with gravity still in the value.
  • Sample number. Starts at 0 for each set and adds 1 every line. A skip or a repeat makes the whole set invalid.
  • Time. Whole milliseconds since the set started, and it must increase every line. Take the value from one clock, either millis() or micros() / 1000, and use the same clock for both sensors.
  • One sensor only. If a reading fails, send E aborted and stop the set. Never send zeros, and never send half a line.

5The three functions to write

void tally_begin(char side)Sends the line in section 1. Resets the sample number.setup()
void tally_sample(unsigned long t_ms, float ux, float uy, float uz, float fx, float fy, float fz)Sends one sample line, as in section 2.loop(), every 10 ms

Build each sample line with snprintf and the pattern "S %lu %lu %+.8f %+.8f %+.8f %+.8f %+.8f %+.8f\n", then send it in one Serial1.write call.

6What comes back

Run the script with no arguments. It finds the port and reads the arm from the header.

fieldmeaning
verdictcorrect or wrong for the whole set, or null when the set could not be scored.
mean_p_wrongMean probability of wrong form. The verdict is wrong at 0.5 or above.
exerciseEAH, EFE or SQZ.
statusscored. Anything else carries diagnostics and no verdict.

7What the board reads back

V correct 0.189 EAH
Vmarker, so the sketch can tell a reply from noise correctcorrect or wrong, or unknown when the set was rejected 0.189mean probability that the form was wrong, three decimals EAHthe exercise, or a single dash when there is none

The script writes one of these per set. It appends them to verdicts.log, and it writes them back to the serial port when it is reading from that port. In loop(), take lines that start with V , parse four tokens, and show them on the screen. Ignore every other line on that port.

The model scores 91.03 % on the left arm and 88.89 % on the right, from 301 and 306 recorded sets by 30 volunteers. Replaying real recordings through this line format reproduced the training features exactly. It has not been tried on a physical board yet.
